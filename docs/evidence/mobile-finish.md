# Screening-room finish evidence

Recorded 29 October 2026 UTC. Software implementation and emulator/browser checks; **not a new physical-phone background pass**.

## Implemented

- One Expo Router screening-room route, no tabs, with dark/light/system appearance.
- Actual local video preview and native duration, rotated dimensions and MIME metadata. Review occurs before stable copying; Upload authorizes copy/hash and native scheduling.
- Durable staged preview after relaunch. Missing/error previews grow with text rather than clipping inside a fixed frame.
- Confirmed progress, waiting/recovery, preparation cancellation, terminal errors, verification and matching receipt. A completion haptic is gated by receipt. Reduced-motion handling is implemented; hardware feel and TalkBack remain unverified.
- Native-only capability ownership. A received job mints a short-lived read-only viewer link; original upload authority never enters JavaScript snapshots or browser markup.
- Browser playback, byte ranges, unchanged original download, single-use two-minute exchange and ten-minute read-only session. Sharing discloses the one-use/expiry boundary before opening the share sheet.
- `artifacts/footage-demo.apk`: standalone ARM64 release-mode local-demo build with development signing. Metro is not required. The separate debug client still requires it.

The [mobile decisions](../architecture/mobile-finish.md) and [viewer architecture](../architecture/receiver-viewer.md) describe interfaces and trust boundaries.

```sh

# Debug APK installed so the runner can read its own fixture authority in memory.
FOOTAGE_BROWSER_CHANNEL=chrome node scripts/verify-receiver-playback.mjs \
  --origin http://<LAN-IP>:1083 --serial emulator-5554 \
  --output artifacts/ui-emulator/viewer-final
# Debug APK initially installed; restores the standalone APK/copy/settings.
python3 scripts/verify-preview-accessibility.py --serial emulator-5554
```

The fresh mobile context copies only its already-authorized read-only cookie in memory. `scripts/record-finish-evidence.py` regenerates the [sanitized consolidated evidence](mobile-finish.json) and [current artifact manifest](artifact.json), checking test counts, native lint, signature evidence and the emulator-installed APK hash.
